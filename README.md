# BaeSenX — Bishop BSXScript 文字翻譯工具　byＡＩ

BaeSenX 是 Windows x64 WPF 工具，針對 Bishop 視覺小說使用的 `BSXScript`（`bsxx.dat`）提供文字匯出、翻譯匯入與 DAT 重建功能。另附舊版 `BSXScript_Tool` DAT 的唯讀 TXT 匯出功能，方便將舊版翻譯人工整理到新版格式。

目前定檔程式碼位於 `t_wpf` 分支，檢視基準提交：`09ecbb05302b85aac7ff8f8904abe0c96361cffb`。

## 功能分流

### 1. 舊版 DAT → TXT（唯讀參考匯出）

此功能專門讀取由舊版 `BSXScript_Tool` 打包的 DAT：

- 只需要舊版 DAT，不需要原始遊戲腳本。
- 辨識 `BSXScript 3.0`～`3.3` 標頭，讀取角色名稱及共用訊息表（對話／選項）。
- 會檢查索引、UTF-16LE 字串終止符及實際檔案邊界。
- 舊版工具可能留下不正確的字串區大小欄位；角色字串區以後續訊息索引表為實際邊界，訊息字串區以檔案 EOF 為實際邊界，不會盲目依賴過期大小欄位。
- 匯出 UTF-8（含 BOM）參考 TXT，保留原索引順序；最後字串結束符之後的尾端資料會以 Base64 註解記錄。
- 不修改 DAT、不自動比對、不合併翻譯，也不會重新打包舊版 DAT。

這份舊版參考 TXT **只供人工比對**。請自行將需要的翻譯整理到由新版原始 `bsxx.dat` 匯出的 BaeSenX TXT，再使用新版功能打包。

### 2. 新版原始 DAT → TXT → 新 DAT

此功能負責正式翻譯作業：

- 支援 `BSXScript 3.0`、`3.1`、`3.2`、`3.3` 格式。
- 完整讀取角色名稱表及共用訊息表，包含一般對話與選項文字。
- 匯出 UTF-8（含 BOM）翻譯 TXT。
- 匯入繁體中文或其他語言翻譯，重建 UTF-16LE 字串區、索引表及相應標頭位址／大小欄位。
- 匯入前核對 `◇` 原文及索引，避免將翻譯套用到不同版本或錯誤位置。
- 匯入後重新讀取輸出 DAT，驗證全部字串；並逐位元組確認 Opcode 區段與來源相同。
- 另存新 DAT，不會覆蓋來源 `bsxx.dat`。
- TXT 匯出採用暫存檔及原子替換，避免寫入中斷留下不完整檔案。

**建議固定使用最初的原始日文 `bsxx.dat` 作為打包基底。** 若要繼續修改已翻譯的 DAT，先從該翻譯版 DAT 重新匯出對應的新版 TXT，再修改其中的 `◆` 翻譯行。不可將最初原始 DAT 匯出的 TXT，直接套用到已翻譯 DAT；兩者的 `◇` 原文不同時，程式會停止打包。

## 使用方式

### 舊版 DAT 參考匯出

1. 執行 `BaeSenX.exe`。
2. 在「舊版格式轉換」區按「選擇舊版 DAT」，選取舊版 `BSXScript_Tool` 產生的 DAT。
3. 確認程式讀取完成後，按「匯出舊版 DAT → TXT」。
4. 使用文字編輯器開啟參考 TXT，依索引比對舊版翻譯。
5. 這份 TXT 不會自動套用到新版腳本；請自行複製需要的翻譯到新版 BaeSenX TXT。

### 新版 DAT 翻譯與打包

1. 執行 `BaeSenX.exe`。
2. 在「新版文字匯出／打包」區按「選擇新版 bsxx.dat」，選取未經舊版工具改寫的原始腳本。
3. 按「匯出新版翻譯文字檔」，產生 BaeSenX TXT。
4. 使用 Notepad++ 等文字編輯器開啟 TXT。
5. 只修改每筆資料中以 `◆` 開頭的翻譯行；以 `◇` 開頭的是原文，請保留。
6. 保留標記及索引，例如 `◆B0000123◆`，只修改其後的文字。
7. 儲存 TXT，回到 BaeSenX 按「匯入新版 TXT 並打包 DAT」。
8. 選取翻譯 TXT，將輸出另存為新 `.dat` 檔。
9. 先備份遊戲原始檔，並在遊戲副本中測試。放回遊戲時，請使用遊戲原本要求的檔名 `bsxx.dat`；不要假設引擎會自動載入 `bsxx_zh.dat`。
10. 確認遊戲能正常啟動、顯示文字及讀取存檔後，再考慮套用到正式遊戲目錄。

## 翻譯文字格式

新版 TXT 使用 `◇` 原文行及 `◆` 翻譯行：

```text
# BaeSenX Translation Text v1
# A = Character names
# B = Message table (dialogue and choice labels)

◇A0000000◇原始角色名稱
◆A0000000◆翻譯後角色名稱

◇B0000000◇原始對話
◆B0000000◆翻譯後對話
```

- `A` 是角色名稱表；`B` 是共用訊息表，包含對話及選項標籤。
- 索引使用十六進位表示。請保留 `◇`、`◆` 及索引內容。
- `◇` 行是原文驗證資料，不要翻譯或刪除。翻譯行若缺少對應的 `◇` 行，程式會拒絕匯入。
- `◆` 行是實際寫入 DAT 的內容。未提供某筆 `◆` 翻譯紀錄時，該筆會維持來源 DAT 原文；將 `◆` 標記後的內容清空，則會寫入空字串。
- 可使用部分翻譯，不必一次修改全部項目；但 TXT 至少要有一筆有效的 `◆` 翻譯紀錄。
- 舊版 `BSXScript_Tool` 的原始標記文字格式亦可匯入；該舊格式不會套用 BaeSenX 的跳脫序列解碼。本文所述「舊版 DAT → TXT」參考匯出檔則僅供人工比對，不要當作新版打包輸入檔。

## 跳脫序列與遊戲文字指令

BaeSenX TXT 需要將部分字元寫成單行可讀格式：

| TXT 表示法 | 匯入後內容 |
|---|---|
| `\\` | 一個反斜線 `\` |
| `\n` | 換行 |
| `\r` | 回車 |
| `\t` | Tab |
| `\uXXXX` | 指定的 Unicode UTF-16 字元 |

遊戲本身的文字控制指令不是 BaeSenX 的跳脫指令。依目前確認的遊戲語法：

- `\b`：放大文字。
- `\A`：主角姓氏。
- `\B`：主角名字。
- `\A\B`：主角完整姓名。

因此，原始遊戲指令在 BaeSenX TXT 中會以雙反斜線形式顯示，例如 `\\b`、`\\A`、`\\B`；匯入時會還原為遊戲使用的單反斜線指令。BaeSenX 不會解讀、改寫或自行執行這些遊戲指令。不要為了讓 TXT 看起來簡短而批次刪除反斜線。

部分遊戲字元可能使用 Unicode 私用區（PUA）。例如目前樣本中顯示為 `` 的字元是 U+E000，遊戲字型可將它映射成愛心圖案；一般文字編輯器可能只顯示私用區字形。BaeSenX 會保留該字元本身，不會自動轉成標準愛心符號。若翻譯不需要該符號，可以只從對應的 `◆` 翻譯行刪除；`◇` 原文仍應保留。

## 安全與相容性

- 正式打包只重建角色名稱及訊息字串表，以及這些區段對應的索引／標頭欄位。
- Opcode 區段不屬於翻譯範圍；輸出前會驗證其與來源檔逐位元組相同。
- 重建後會重新讀取輸出檔，逐筆驗證角色名稱與訊息字串。
- 來源 DAT 不會被覆蓋；輸出路徑若指向來源檔，程式會拒絕執行。
- 匯入內容不得包含 NUL（U+0000）字元；此字元會被拒絕，避免破壞 UTF-16 字串表。
- 若格式簽章、索引、區塊邊界、UTF-16LE 序列或字串終止符不合理，程式會中止，不會猜測或自動修復。
- 字串以 UTF-16LE 寫入；遊戲能否正確顯示中文字，仍取決於遊戲字型及字形資源是否包含所需字元。
- 雖然格式辨識範圍為 BSXScript 3.0～3.3，目前自動回歸測試使用的真實樣本是 3.3；尚未取得 3.0～3.2 的真實樣本完成實測。也尚未對所有 Bishop 遊戲逐款驗證相容性，請先使用遊戲副本測試。

## 回歸測試

GitHub Actions 使用儲存庫內兩份真實樣本執行測試：

| 測試 | 樣本 | 版本／規模 | 目前結果 |
|---|---|---|---:|
| 新版匯出／匯入／重建 | `test/bsxx.dat` | BSXScript 3.3；57 筆角色名稱、36,301 筆訊息／選項 | 85 項斷言通過 |
| 舊版 DAT 唯讀匯出 | `test/cn_bsxx.dat` | BSXScript 3.3；57 筆角色名稱、36,301 筆訊息／選項 | 28 項斷言通過 |

新版測試涵蓋：

- 真實樣本讀取及角色／訊息表數量。
- TXT UTF-8 BOM、重複匯出及原子替換。
- 不修改翻譯的完整匯出／匯入往返。
- 修改繁體中文、日文、多行文字、Tab、標記符號及補充平面 Unicode 後重新匯入。
- Opcode 位址、大小及內容逐位元組保留；原始資料前綴、尾端資料、索引表及 16-byte 對齊驗證。
- 舊版標記文字匯入、原文不符拒絕、錯誤時不產生輸出檔、NUL 字元拒絕。
- 來源樣本不被修改，以及既有輸出 TXT／DAT 的安全替換流程。

舊版測試涵蓋：

- 角色名稱及訊息／選項完整解析、索引順序及 TXT 內容比對。
- UTF-8 BOM 與字串區尾端資料 Base64 註解。
- 舊版標頭字串區大小欄位與實際邊界不一致時，依相鄰區段及 EOF 限定讀取範圍。
- 拒絕負索引、超出實際 EOF 的索引、無效 UTF-16LE 及缺少 NUL 結束字元的資料。
- 匯出不覆蓋來源 DAT，且來源檔 SHA-256 不變。

以上斷言數是目前 `t_wpf` 定檔提交所使用的測試數；日後增刪測試時，應以最新 Actions 執行結果為準。測試程式位於 `BaeSenX.Tests/` 與 `BaeSenX.LegacyTests/`，不會包進使用者下載的 GUI Artifact。

## Windows x64 建置與下載

- GUI 技術：WPF。
- 目標架構：x64。
- 目標執行階段：.NET Framework 4.8。
- Windows 10／11 x64 使用者端需要可用的 .NET Framework 4.8；乾淨建置環境會透過 NuGet 還原 .NET Framework 4.8 參考組件。

GitHub Actions 工作流程：`.github/workflows/build-win-x64.yml`。

1. 開啟 GitHub 專案的 **Actions**。
2. 選擇 **Build BaeSenX Windows x64**。
3. 可按 **Run workflow** 手動執行；推送至 `t_wpf` 分支且變更符合 workflow 的路徑條件時，也會自動執行。
4. 確認 GUI、兩個測試 runner 均建置成功，且新版與舊版測試步驟通過。
5. 從該次成功執行下載 `BaeSenX-Win10-x64` Artifact，解壓縮後執行 `BaeSenX.exe`。

Artifact 保留 14 天；請從最新成功的 Actions 執行下載，不要依賴過期的舊 Artifact。建置使用 `actions/checkout@v7`、`microsoft/setup-msbuild@v3` 及 `actions/upload-artifact@v7`。

另有 `.github/workflows/diagnose-legacy-bsxx.yml`，用於手動或樣本檔變更後檢查原始／舊版 BSXX 標頭、區段、索引及訊息字串邊界；它是診斷工作流程，不是一般使用者的建置或打包流程。
